# 群友画像文件格式

每位群友一个文件，跨次运行累积。SKILL.md `Step 3.7` 加载、`Step 8.5` 更新。

## 路径与命名

```
{folder}/profiles/{wxid}-{nickname}.md
```

- `{wxid}` 是 wx-cli 返回的稳定 id（如 `wxid_abc123` 或 `onlytiancai`）。
- `{nickname}` 用最近一次出现时的备注/昵称，文件系统不允许的字符（`/ \ : * ? " < > |` 和控制符）换 `_`，emoji/中文保留。
- 一个用户**只有一个文件**。昵称变了就 rename（找 `{wxid}-*` 前缀匹配），不要新建。

## 文件结构

```markdown
---
wxid: wxid_abc123
display: 蛙总
aliases:
  - frog
  - frog总
first_seen: 2026-03-01
last_seen: 2026-05-14
total_messages: 1247
batch_count: 23
tags:
  - 常态空头
  - Claude 工具链玩家
  - Mac 开发者
---

# 蛙总

## 角色定位

（2-4 行散文，描述这个人在群里的位置。避免人格判断，描述行为模式。）

群里最常态的多空辩论方，长期空 SPY。技术上偏 Mac + Claude Code，会写 Bun 脚
本。生活区基本不发言。

## 常聊话题

- 美股 / 期权 / 做空
- Claude 系列模型实测
- Bun / Mac / 终端工具链

## 经典语录

按时间倒序，每条带日期。**append-only，不要重写**。

- 2026-05-14：「上周不算，那是市场不理性」
- 2026-05-12：「这 SPY 必空，今天必空」
- 2026-04-28：「Bun 在 Mac 上比 Node 慢得跟蜗牛似的」

## 关键事件

时间序，记录这个人在群里的"标志性时刻"。**append-only**。

- 2026-05-14：第三周空 SPY 被翻旧账后改口"市场不理性"
- 2026-04-28：发起 Bun 性能对比实验，3 天后承认是自己脚本问题

## 与其他人的关系（可选）

只在有稳定模式时写。一次性互动不写。

- 与老王：固定的辩论对手，老王经常给反例
- 与阿喵：技术互助，互相 review 对方的 PR

## 当日观察（最近 N 次）

最近 3-5 次出现的当日观察，超过就把最老的删掉（控制文件大小）。

### 2026-05-14

### 2026-05-13
全天没发美股相关，只聊 Claude。可能账户回血了。
```

## frontmatter 字段

| 字段 | 类型 | 更新策略 |
|---|---|---|
| `wxid` | string | 永不变 |
| `display` | string | 每次运行用最新值覆盖 |
| `aliases` | list | 出现新昵称时追加 |
| `first_seen` | date | 创建时写入，永不变 |
| `last_seen` | date | 每次运行覆盖为本次日期 |
| `total_messages` | int | 累加（本次消息数 + 旧值） |
| `batch_count` | int | +1 |
| `tags` | list | 标签变化时增删，建议 ≤ 6 个 |

## 更新规则

`Step 8.5` 对本批 **3+ 条**且出现在「群友画像」板块的用户更新：

1. 读旧文件（如果存在），保留 frontmatter 的 `first_seen`、append-only 区块。
2. 覆盖更新：`display`、`last_seen`、`total_messages`（累加）、`batch_count`（+1）、`aliases`（合并去重）、`tags`（按本批更新）。
3. **append**：`经典语录`、`关键事件` 追加新内容，**不要删旧的**。
4. `当日观察`：追加新一节，超过 5 节就删最老的。
5. `角色定位` 和 `常聊话题`：基于累积数据**重写**，但变化要平滑（不要因为单次表现完全推翻）。

## 隐私红线

**永不写入画像**：

- 账户余额、持仓金额、薪资数字
- 真实姓名（除非他自己长期用真名）
- 住址、电话、邮箱、身份证号
- 健康 / 婚姻 / 家庭隐私
- 政治敏感观点

哪怕用户在群里主动说过也不要写进画像 —— 画像是长期累积的，要按最严的标准过滤。

## 回溯画像（backfill）

用户说 "回溯画像" / "初始化画像" / "backfill profiles" 时：

1. 确认目标群（没指定就问）。
2. 列出 `{folder}/` 下所有简报 .md 文件 + `history-digests.jsonl`。
3. 按 10-15 份一批读旧简报。
4. 出现在 **3+ 份**简报里的用户，从历史的排行榜、画像段落、引用里抽内容，初始化画像文件。
5. 跑完报告：创建了 N 个画像、覆盖了 M 个用户。
